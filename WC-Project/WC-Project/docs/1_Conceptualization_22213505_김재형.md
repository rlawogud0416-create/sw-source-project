## 1. Business purpose

### 1.1 Project background

<img width="189" height="267" alt="image" src="https://github.com/user-attachments/assets/c1e17695-9922-4bdc-a611-608c96b6f0ba" />

[그림 1-1] 옷 고르는 모습

| 응답 항목 | 비율(%) |
| :--- | :---: |
| 매일 아침 옷차림을 고민한다 | 78.4 |
| 일기예보 기온만 보고 옷을 고른다 | 65.2 |
| 옷을 잘못 입어 더위/추위를 겪은 경험이 있다 | 71.8 |
| 옷차림 추천 서비스가 필요하다고 생각한다 | 58.3 |

[표 1-1] 직장인 출근 준비 관련 일반 통계 (가상 예시)

우리 생활 속에서 꼭 필요한 것을 말하라고 하면 대부분 의식주를 말한다. 그중 의(衣)에 해당하는 옷을 우리는 고민하느라 상당한 시간을 할애한다. 특히 환절기나 기온 변화가 심한 날에는 일기예보의 온도 숫자만 보고 옷차림을 결정했다가 춥거나 더워서 낭패를 보는 경우가 많다. 바쁜 아침 출근 시간에 옷장을 뒤적이며 날씨에 맞는 상의와 하의, 아우터를 조합하는 과정은 불필요한 시간 낭비와 결정 피로를 유발한다.

만약 이러한 옷 조합 과정이 자동화된다면 어떨까? 사용자가 자신의 옷을 웹에 미리 등록해 두고 외출할 시간의 기온만 입력하면, 시스템이 옷의 두께 데이터를 분석하여 자동으로 적절한 코디 조합을 즉시 추천해주는 웹 서비스를 통해 사용자는 옷 고르는 시간을 절약할 수 있을 뿐만 아니라, 날씨에 맞는 옷차림을 신속하게 결정할 수 있을 것으로 기대된다.

### 1.2 Goal

\- 사용자의 옷을 카테고리(상의/하의/아우터)와 두께별로 웹에서 쉽게 등록·관리할 수 있어야 한다.

\- 사용자가 입력한 기온을 기준으로 적절한 옷 조합(상의 + 하의 + 아우터)을 자동으로 추천할 수 있어야 한다.

\- 카테고리, 두께 레벨, 이름 등을 기준으로 등록된 옷을 검색·필터링할 수 있어야 한다.

## 4. Concept of operation

### 1) 옷장 데이터 로드

| Purpose | 사용자가 이전에 저장한 옷장 데이터를 웹 화면에 표시하도록 한다. |
| :--- | :--- |
| Approach | 사용자가 웹 페이지에 접속하면 백엔드가 저장소(파일 또는 DB)에서 옷 데이터를 읽어 JSON 형태로 프론트엔드에 전달하고, 프론트엔드는 이를 화면에 렌더링한다. |
| Dynamics | 사용자가 웹 페이지에 처음 접속하거나 새로고침할 경우 |
| Goals | 사용자가 이전에 저장해 둔 옷장 상태를 유실 없이 그대로 불러와 사용할 수 있게 한다. |

### 2) 신규 의류 등록

| Purpose | 사용자가 새로 구매하거나 등록할 옷을 시스템에 추가할 수 있게 한다. |
| :--- | :--- |
| Approach | 사용자가 입력 폼에서 카테고리(상의/하의/아우터), 이름, 두께 레벨(1~5)을 입력 후 등록 버튼을 누르면, 백엔드가 새 옷 객체를 생성하여 옷장 리스트에 추가하고 저장소에 반영한다. 잘못된 입력값(빈 값, 범위 외 두께)은 예외 처리한다. |
| Dynamics | 사용자가 '옷 추가' 기능을 선택한 경우 |
| Goals | 사용자의 실제 옷장 변화를 시스템 내부에 정확하게 반영할 수 있게 한다. |

### 3) 옷장 조회 및 필터링

| Purpose | 시스템에 등록된 옷의 전체 또는 특정 카테고리 목록을 확인할 수 있게 한다. |
| :--- | :--- |
| Approach | 백엔드가 보관 중인 옷 객체 리스트를 카테고리 필터 조건에 따라 정제하여 프론트엔드로 전달하고, 프론트엔드는 표 또는 카드 UI 형태로 사용자에게 보여준다. |
| Dynamics | 사용자가 '내 옷장 보기' 또는 카테고리 필터 버튼을 선택한 경우 |
| Goals | 사용자가 현재 보유한 옷의 종류와 두께 레벨을 직관적으로 파악할 수 있게 한다. |

### 4) 기존 의류 수정

| Purpose | 잘못 등록된 옷의 정보를 사용자가 직접 수정할 수 있게 한다. |
| :--- | :--- |
| Approach | 사용자가 옷 목록에서 수정 버튼을 누르면 기존 정보가 채워진 폼이 나타나고, 사용자가 값을 변경하여 저장하면 백엔드가 해당 옷 객체를 갱신한 뒤 저장소에 반영한다. |
| Dynamics | 사용자가 특정 옷의 수정 기능을 선택한 경우 |
| Goals | 데이터의 정확성을 유지하여 추천 결과의 신뢰도를 높인다. |

### 5) 기존 의류 삭제

| Purpose | 사용자가 더 이상 입지 않는 옷을 시스템에서 제거한다. |
| :--- | :--- |
| Approach | 사용자가 삭제 버튼을 누르고 확인 절차를 거치면, 백엔드가 해당 옷 객체를 옷장 리스트에서 제거한 뒤 저장소에 반영한다. |
| Dynamics | 사용자가 특정 옷의 삭제 기능을 선택한 경우 |
| Goals | 불필요한 데이터를 제거하여 코디 추천 시 안 입는 옷이 노출되는 것을 방지한다. |

### 6) 기온 맞춤형 코디 추천

| Purpose | 사용자가 입력한 기온에 가장 적합한 외출복 조합을 추천한다. |
| :--- | :--- |
| Approach | 사용자가 기온(℃)을 입력하면, 시스템은 내부 기준표를 통해 해당 기온의 적정 두께 레벨을 산출한다. 적정 두께 조건에 부합하는 상의·하의·아우터 객체만 필터링한 뒤, 각 카테고리에서 무작위로 1개씩 선택하여 1세트의 코디를 화면에 표시한다. |
| Dynamics | 사용자가 외출 전 기온을 입력하고 코디 추천 버튼을 누른 경우 |
| Goals | 날씨와 옷의 두께를 논리적으로 매칭하여 최적의 코디를 빠르게 제안함으로써 사용자의 결정 피로를 없앤다. |

### 7) 추천 결과 재요청

| Purpose | 사용자가 추천된 코디가 마음에 들지 않을 경우 다른 조합을 다시 받을 수 있게 한다. |
| :--- | :--- |
| Approach | 추천 결과 화면의 '다시 추천' 버튼을 누르면, 시스템이 동일한 기온 조건에서 이전과 다른 조합이 나오도록 다시 무작위 선택을 수행한다. |
| Dynamics | 사용자가 추천 결과에 만족하지 않은 경우 |
| Goals | 한 번의 추천에 갇히지 않도록 다양성을 제공한다. |

### 8) 옷 데이터 저장

| Purpose | 변경된 옷장 데이터를 영구적으로 보존한다. |
| :--- | :--- |
| Approach | 사용자가 옷을 추가·수정·삭제할 때마다 백엔드가 즉시 메모리상의 최신 옷 데이터를 저장소(JSON 파일 또는 DB)에 직렬화하여 기록한다. |
| Dynamics | 옷장 데이터에 변경이 발생할 때마다 |
| Goals | 데이터 손실 없이 최신 상태를 안전하게 보존한다. |

## 5. Problem statement

본 시스템은 사용자의 의류 데이터를 웹 환경에서 관리하고, 입력된 기온이라는 환경 변수에 맞춰 최적의 코디 조합을 산출해야 한다. 아래는 시스템이 해결해야 할 핵심 과제들에 대한 명세이다.

### 5.1 의류 속성의 정량화 및 객체화

시스템이 다루는 '옷'은 종류가 다양할 뿐만 아니라 '두께감'이나 '계절감'처럼 사람마다 주관적으로 느끼는 정성적 속성을 지닌다. 시스템이 이를 논리적으로 연산하고 특정 기온 데이터와 비교하기 위해서는, 이러한 주관적 요소를 1~5단계와 같은 객관적 수치로 변환하는 기준이 필요하다. 또한 상의, 하의, 아우터 각 카테고리의 특성을 클래스로 추상화하여 일관된 인터페이스로 다룰 수 있어야 한다.

### 5.2 기온 기반 추천 알고리즘 설계

시스템은 사용자가 입력한 기온을 정확히 해석하여, 전체 옷장 데이터 중 해당 기온에 부합하는 두께 레벨의 객체들을 필터링해야 한다. 단순히 옷을 나열하는 수준이 아닌, 필터링된 객체들 사이에서 상의·하의·아우터가 누락 없이 하나의 완전한 세트로 조합되도록 알고리즘을 설계해야 하며, 사용자가 다른 조합을 원할 때 즉시 새로운 조합을 제공할 수 있어야 한다.

### 5.3 데이터 저장 구조 및 영속성 확보

수십 벌의 옷 데이터를 효율적으로 탐색·관리하기 위해 객체지향적 분류 체계가 필요하다. 또한 웹 서비스의 특성상 페이지를 닫거나 새로고침해도 데이터가 휘발되지 않아야 하므로, 서버 측 저장소(파일 또는 데이터베이스)에 옷 데이터를 직렬화하여 영구 저장하고, 시스템이 다시 시작되었을 때 데이터를 안전하게 복원할 수 있는 구조가 요구된다.

### 5.4 사용자 편의성 (UX)

웹 환경의 장점을 살려 사용자가 마우스 클릭과 간단한 입력만으로 모든 기능을 직관적으로 이용할 수 있어야 한다. 잘못된 입력값(빈 값, 범위를 벗어난 두께 레벨, 숫자가 아닌 기온 등)이 들어와도 시스템이 비정상 종료되지 않도록 견고한 입력 검증 및 예외 처리가 필요하며, 추천 결과는 깔끔한 UI로 한눈에 파악할 수 있게 출력되어야 한다.

## 6. Glossary

| 용어 | 설명 |
| :--- | :--- |
| WC | 본 프로젝트의 이름(Weather Coordinator)이다. |
| 사용자 (User) | 웹 페이지에 접속하여 옷장 등록 및 코디 추천 기능을 이용하는 사람이다. |
| 카테고리 | 옷의 종류를 의미하며, 본 시스템에서는 상의(Top), 하의(Bottom), 아우터(Outer)로 구분한다. |
| 두께 레벨 | 옷의 두께와 계절감을 정량화한 자체 기준으로, 1단계(여름용)부터 5단계(한겨울용)까지 5단계로 구성된다. |
| 코디 (Outfit) | 상의, 하의, 아우터가 각각 1개씩 포함된 한 벌의 옷 조합을 의미한다. |
| 직렬화 | 메모리상의 옷 객체 데이터를 파일이나 DB에 저장하기 위해 문자열(JSON 등) 형태로 변환하는 과정이다. |
| 다형성 | 부모 클래스(Clothing) 타입으로 자식 클래스(Top, Bottom, Outer)의 객체를 일관되게 제어할 수 있는 객체지향의 성질이다. |
